## 1.2.35 뱅가드 기능 삭제

플레이 설정과 알림창에서 뱅가드 선택·횟수 설정을 삭제하고, 전용 화면 인식·실행·알림 명령·참조 이미지도 제거했습니다. 콘텐츠는 어비스와 레이드만 표시합니다. 이전에 뱅가드가 선택돼 있거나 지원하지 않는 선택값이 저장돼 있으면 어비스로 처리합니다. 예전 레이드 설정만 있는 설치의 선택값은 유지합니다.

어비스·레이드의 음식 인식(여행자 간식·삶은 계란), 6번 스킬 10~20초 무작위 간격, 파티 반복·난이도 확인·전멸 처리·진행 기록을 유지했습니다. 지원 선택값/이전 설정 2,015개 검사와 어비스·레이드 회귀, APK 빌드·기존 서명·알림 버튼 리소스 검증을 수행했습니다. 실제 Android 기기의 알림창/터치·게임 실행은 미검증입니다. 아래 예전 버전 설명은 변경 이력이며 삭제한 기능의 현재 사용 안내가 아닙니다.

## 1.2.34 삶은 계란 음식 인식 추가

기존 여행자 간식에 사용하던 갈색 판정을 유지하면서, 보내주신 삶은 계란의 노른자·흰자·껍질·어두운 테두리 배치를 추가로 확인합니다. 같은 음식 아이콘 위치에서 판정하며 어비스·레이드의 기존 음식 사용 순서와 버프 확인을 유지합니다. 진행 기록의 ‘갈색 아이콘’ 표시는 ‘음식 아이콘’으로 정리했고 레이드 사용 안내에도 현재 6번 스킬 무작위 간격을 반영했습니다.

제공 아이콘과 합성 크기/밝기/색상·폰/S7/Y700 HUD 배치 288개, 기존 간식·부분 누락·음식 없음·다른 위치·장면 전환·중복 사용 방지를 포함한 1,175개 검사를 통과했습니다. 제공 아이콘은 기존 판정에도 잡히므로 실제 실패 원인을 확정하지 않았습니다. 제어한 색상 변화 144개에서 추가 판정이 기존 갈색 조건의 누락을 보완했습니다. 실제 Android/게임 OCR·터치·장시간 실행은 미검증입니다.

## 1.2.33 6번 스킬 무작위 자동 사용

어비스(혼자·파티)와 레이드에서 스킬 이름·직업·아이콘·활성 표시를 조건으로 삼지 않고, 맨 오른쪽 6번 스킬 슬롯을 한 번씩 누릅니다. 전투 확인 뒤 첫 사용까지 10~20초를 기다리고, 이후 매번 새로운 10~20초 간격을 뽑습니다. 인식 주기와 화면 전환 확인에 따라 실제 터치 시점은 늦어질 수 있습니다.

기존 어비스의 궁극기 활성 인식과 레이드의 고정 20초 주기를 이 공통 동작으로 교체했습니다. 로딩·매칭·영상·보상·행동불능·전멸·중지 중에는 누르지 않습니다. 잠깐 인식하지 못한 프레임에는 누르지 않고 전투가 다시 확인된 뒤 한 번만 처리합니다. 기존 화면 비율·HUD 배치 보정을 사용하며 이름이나 아이콘을 맞추기 위한 별도 인식은 하지 않습니다.

제어한 시계로 어비스·레이드 각 6,000회 사용과 제공 화면의 아이콘 변경·이름 가림을 검사했습니다. 폰·S7·Y700 좌표 재생 및 기존 회귀 검사, APK 빌드·기존 서명 검증을 통과했습니다. 실제 Android/게임의 터치·ML Kit OCR·장시간 실행은 미검증입니다. 이전 기록의 ‘20초 마지막 스킬’ 설명은 이 버전부터 대체됩니다.

## 1.2.32 화면 분석·기록 처리 최적화

같은 화면에서 같은 색상의 선택 상태를 반복 계산하는 작업을 줄였습니다. 기존 판정 조건과 표본 좌표를 유지하며 프레임마다 최대 256개 색상만 보관합니다. 캐시 공간이 충돌하면 원래 색상을 다시 계산하며, 다음 화면의 픽셀이나 판정을 추측하지 않습니다.

진행 기록의 내용이 같으면 표시 문자열과 날짜 포맷터를 재사용합니다. 기록 화면이 배경으로 내려가거나 닫히면 해당 화면의 갱신을 멈추고, 다시 열면 최신 기록을 읽습니다. 일반 기록 15분 정리·오류 보관은 유지합니다.

270개 색상 비율 판정의 float 비트가 이전 버전과 같았고, 제어한 시험 화면의 HSV 변환 호출은 약 65.42% 줄었습니다. 실제 휴대전화의 전체 처리 속도·FPS·발열·배터리 개선율은 측정하지 않았습니다. 상세 검사와 한계는 validation/OPTIMIZATION-1.2.32.md를 참고하세요.

사용자 요청에 따라 앞으로 모바일 수정 작업은 검사·빌드·서명 확인을 마친 뒤 별도 재승인 없이 업로드하고 업데이트 정보를 등록합니다.

## 1.2.31 파티 반복 난이도 선택 인식

파티 반복에서 난이도 글자를 놓쳤을 때 예전 고정 좌표를 누르던 경로를 제거했습니다. ‘매우 어려움’과 ‘매우 어려움2’를 구분하고, 단어/숫자가 분리되거나 줄바꿈된 경우에도 실제 글자 위치를 찾습니다. 여러 탭이 한 줄로 합쳐져 개별 영역을 찾을 수 없거나 후보가 중복되면 ‘난이도 글자·버튼 위치 재확인 대기’를 표시합니다.

난이도를 선택한 뒤 2.5초 동안 화면 반영을 기다리고 선택된 색상을 두 번 확인한 후 다음 설정이나 입장을 진행합니다. 인식 누락·다음 회차·목록 복귀·로딩·매칭·초기화 때 이전 확인이 새 입장을 대신하지 않습니다. 다른 앱 전환 시 정상 정지는 유지합니다.

제어한 OCR/합성 화면 522개 검사와 난이도별 파티 반복 총 2,160회를 통과했습니다. 반복은 엔진당 가상 4시간 120회이며, 실제 기기에서 4시간 실행한 뜻은 아닙니다. 상세 검증과 한계는 validation/DIFFICULTY-1.2.31.md에 있습니다. 새 실패 화면이 없어 사용자의 실기기 원인은 확정하지 않았습니다.

## 1.2.31에 포함된 진행 기록 자동 정리

일반 진행 기록은 앱 프로세스의 고정된 15분 주기마다 자동 정리합니다. 매크로가 정지한 동안에도 정리하며, 절전으로 타이머가 늦어지면 기록을 다시 읽거나 추가할 때 지난 정리를 반영합니다. 앱의 현재 상태·판수·게임 진행은 변경하지 않습니다.

터치 요청 거절·취소·연속 실패·응답 지연, 화면 캡처·문자 인식·화면 분석·준비 오류, 난이도 불일치 정지와 접근성 중단은 명시적인 오류 기록으로 분리합니다. 오류에는 날짜·시간과 [오류] 표시를 붙이고 앱 내부 파일에 보관해 재실행 후에도 표시합니다. 일반 기록의 용량 정리나 15분 정리로 오류를 삭제하지 않습니다. 정상 대기·사용자 정지·모드 변경은 일반 기록입니다.

펼친 진행 기록 화면은 정리 결과를 반영하고 복사는 현재 남은 기록을 읽습니다. 파일 저장에 실패하면 오류는 현재 실행 메모리에 남기고 보관 실패 안내를 표시합니다. 다음 정리 시 다시 저장하며 읽지 못한 기존 오류 파일을 덮어쓰지 않습니다.

검증 범위는 validation/HISTORY-1.2.30.md를 참고하세요. 제어한 시계와 Handler 대역을 사용하는 검사이며, 실제 Android 기기의 15분 대기·저장소·화면 터치는 미검증입니다.

## 1.2.29 전멸 퇴장·배너 메뉴 인식

어비스에서 빨간 ‘전멸하였습니다’ 안내가 확인되면 미니맵 옆 나가기 아이콘의 모양을 찾습니다. 별도 화면에서 ‘던전에서 퇴장하시겠습니까?’와 취소·초록색 나가기 버튼이 확인된 뒤 실제 나가기 글자 위치를 누릅니다. 개인 행동불능·여기서 부활과 구분하며, 전멸을 보지 않은 퇴장창에서는 자동으로 나가지 않습니다. 인식 누락 중에는 부활·공격·클리어 처리를 하지 않고 퇴장 화면을 다시 확인합니다. 밖으로 돌아온 화면을 두 번 확인하면 기존 반복을 이어갑니다. 전멸은 완료 횟수에 포함하지 않습니다.

이벤트 배너로 메뉴가 아래로 밀려도 실제 어비스·레이드 글자 영역과 같은 행의 메뉴 문맥을 찾습니다. 합쳐진 OCR 줄에서는 개별 글자 영역을 사용하고, 위치가 변하는 동안에는 기존 1.5초 안정 확인을 유지합니다. 과거 ‘어비스 + 망령의 탑’ 메뉴와 현재 ‘어비스 + 레이드’ 메뉴를 처리하며, 파티 매칭의 분류 선택창·단독 문구·중복된 후보에서는 추정 위치를 누르지 않습니다.

제공한 전멸/퇴장/배너 화면의 픽셀과 제어한 OCR, 배너가 없는 행 위치·밀린 행·분리/병합 글자, S7/Y700 분석 크기와 상단·하단 고정/비율 배치에서 검사했습니다. 전멸 퇴장 240회 가상 반복과 두 단계의 취소 후 새 화면 복구를 포함합니다. 기존 전체 회귀, Android 컴파일·기존 서명·16KB 정렬·ZIP 검증도 통과했습니다. **배너 없는 배치는 합성이며 실제 ML Kit OCR·연결 기기의 터치·게임 서버에서의 퇴장은 미검증입니다.**

## 1.2.28 파티 재입장·터치 취소 복구

어비스의 입장·다른 던전 가기 등 이동 버튼 터치가 한 번 취소되면 바로 전체 실행을 멈추던 처리를 보완했습니다. 잠깐 기다린 뒤 새로 캡처한 화면에서 버튼을 다시 확인하며, 취소 전에 얻은 OCR 결과나 이전 좌표를 재사용하지 않습니다. 기존 같은 동작의 2.5초 재시도 간격을 유지하고 3회 연속 실패하면 멈춥니다. 음식·궁극기 등 한 번만 사용하도록 기록하는 동작은 취소 시 기존 정지 처리를 유지합니다.

동시에 두 자동 터치를 보내지 않으며 이전 실행의 늦은 터치 응답이 새 실행을 멈추지 않도록 실행/요청을 구분합니다. 터치 결과 콜백이 4초 동안 오지 않으면 계속 누르지 않고 접근성 확인 안내와 함께 멈춥니다. 중지·다른 앱 전환·게임 창 재확인 조건은 유지합니다.

던전 상세의 ‘혼자하기 함께하기’가 한 OCR 줄로 합쳐지는 경우도 처리합니다. 개별 ‘함께하기’ 글자 영역을 못 찾았을 때는 오른쪽 탭의 선택 색이 확인된 경우에만 다음 설정을 읽습니다. 선택이 불명확하면 버튼 위치를 추측하지 않습니다. 하단 ‘입장하기’가 두 줄로 나뉘는 경우도 실제 글자 영역을 합쳐 읽습니다.

기존 전체 회귀, 3,039개 터치 수명/재시작 검사, 90개 합성 상세 인식 검사, S7 비율의 600회 취소→새 화면→재입장 재생(600회 가상 취소·3,000개 좌표·33,601개 단언), Android 전체 컴파일·기존 서명·16KB 정렬·ZIP/알림 벡터 검증을 통과했습니다. **가상 콜백·제어한 OCR 검사이며 실제 Android 터치나 S7 매칭 서버를 실행한 검사는 아닙니다.** 로그만으로 터치가 취소된 원인이나 55초 인식 지연의 정확한 화면 상태를 확정하지 않았습니다.

## 1.2.27 고양이 모양 버튼

메인·설정·선택 목록·업데이트 창·게임 위 조작 버튼과 떠 있는 조작 아이콘에 고양이 귀 모양을 적용했습니다. 넓은 버튼에는 수염 장식도 표시합니다. 알림창 조작 버튼도 같은 모양이며, 선택 강조 색과 누름 효과를 유지합니다. 글자는 장식 아래에 놓이도록 안쪽 여백을 조정했습니다.

기존 Android Button과 버튼 ID, 클릭 연결, 선택·비활성화 상태, 키보드 포커스 및 터치 영역을 유지합니다. 배경 Drawable을 바꾸며 별도 터치 가로채기나 모양에 따른 터치 제한은 추가하지 않았습니다. 스위치는 Android의 기존 모양과 기능을 유지합니다. 게임 위 조작 아이콘의 드래그와 눌러 펼치기도 그대로입니다.

검사: 72개 벡터 크기·밀도·모서리 조합(테두리 밖 그리기 방지·글자 중심·비활성화·예제 라벨 폭), 기존 UI·업데이트 검사 296개, 클릭/터치/스위치/닫기 콜백 12개 원문 비교와 비 UI 클래스 29개 동일성 확인, 전체 Java 컴파일·APK 패키징·알림 벡터 리소스·기존 서명·16KB 정렬·ZIP 무결성을 통과했습니다. **벡터 시각 검사는 AWT 어댑터이며 Android 실행 화면이 아닙니다. 실제 기기에서의 버튼 터치·스크롤·포커스는 아직 검증하지 않았습니다.**

## 1.2.26 앱 이름 변경

## 1.2.25 S7 파티 재입장 수정

입장을 요청한 뒤 로딩·매칭 화면을 놓치고 전투 문구가 간헐적으로만 읽히면, 기존 입장 준비 상태가 풀리지 않아 클리어 후 다음 던전으로 진행하지 못하는 경로를 재현하고 수정했습니다. 실제 입장을 요청한 경우에만 15초 안의 두 번의 독립적인 전투 관측을 인정하며, 중간의 단순 인식 누락은 허용합니다. 시간이 지나거나 상세·목록·메뉴로 돌아가면 이전 관측을 버립니다. 대기 시간만으로 상태를 풀거나 버튼 위치를 추정하지 않습니다.

새 검사: 간헐적 인식·오래된 관측·상세 복귀·초기화와 혼자/파티 400회 가상 반복을 포함한 2,826개 상태 단언, 폰·S7·Y700 비율과 709/848/960px 분석 크기의 324개 합성 보상 화면 및 90회 파티 재입장 재생(1,608개 단언)을 통과했습니다. 기존 회귀 검사와 APK 빌드·기존 서명·16KB 정렬·ZIP 검증을 함께 수행했습니다.

## 1.2.24 어비스 입장·재입장 인식 수정

던전 선택 후 ‘우연한 만남 스위치 인식 대기’가 반복되는 로그에 맞춰 상세 화면 인식을 보완했습니다. 기존의 좁은 세로 탐색 범위를 바꾸고, ‘우연한’·‘만남’이 나뉘거나 안내 문구와 한 줄로 인식되는 경우도 해당 항목의 실제 행을 찾습니다. 스위치는 그 행에서 색상과 모양을 확인하고, 켜진 것이 확인되면 실제 ‘입장하기’ 글자 위치를 누릅니다. 상태가 불분명하면 항목·상태·입장 버튼 중 어느 단계인지 구분해 표시합니다.

던전 상세 화면을 확인한 프레임은 뒤에 비치는 보상·목록 문구와 함께 판정하지 않습니다. 입장 준비 중 잠깐 글자를 놓쳐도 보상 화면으로 전환하지 않으며, 던전 목록으로 돌아가는 경우에는 연속 확인을 거칩니다. 로딩·매칭·영상 또는 연속 전투 화면으로 정상 진행을 확인하면 이 준비 상태를 해제합니다.

추가 검사: 폰·S7·Y700 비율과 709/848/960px 분석 크기에서 162개 합성 상세 화면 조합, 분리/병합된 OCR 문구, 이동한 행, ON/OFF/불명 상태와 보상/목록 배경 혼동 검사 921개, 로그 흐름을 재현한 상태 전환 검사 22개를 통과했습니다. 기존 회귀 검사와 APK 빌드·동일 서명·16KB 정렬·ZIP 검증도 통과했습니다.

**제공된 자료는 상태 로그이며 실제 실패 화면·OCR 결과는 없었습니다. 위 검사는 제어한 OCR과 합성 컨트롤을 사용하므로 해당 기기의 실제 입장 성공을 확인한 것은 아닙니다.** 업데이트 후에도 멈추면 그 순간의 전체 상세 화면 캡처와 새 로그로 확인해야 합니다.

## 1.2.22 태블릿 화면 인식 수정

## 1.2.21 태블릿 화면 대응

- 창 위치·크기가 바뀌면 연속 두 번 확인한 후 조작하며, 게임 창을 찾지 못하거나 창이 바뀌면 이전 좌표로 누르지 않습니다. 전투·완료 횟수와 레이드 무제한 반복 조건은 유지합니다.
- 화면 보정으로 달라지는 아이콘 세로 비율에 대해 레이드 날개·나가기·메뉴와 뱅가드 탭의 추가 검색을 지원합니다. 기존 모양·장면 확인과 사각형 아이콘 배제 조건은 유지합니다.
- 음식 버프는 세로 두께가 있는 연속 행을 확인합니다. 축소 과정의 1~2줄 색상 흔적이 여러 버프 줄로 오인되는 사례를 수정했습니다.

## 1.2.20 화면 분석 최적화

같은 화면 안에서 반복하는 픽셀 읽기를 필요한 영역의 타일 읽기로 묶었습니다. 픽셀 데이터 캐시는 화면당 최대 512KiB이며 프레임 사이에는 공유하지 않습니다. 한도를 넘는 좌표는 기존 직접 읽기로 처리합니다. 음식·부활·난이도·궁극기·스킬·출항선 복귀 등 판정 조건은 유지합니다.

- 실제 이미지와 제어한 OCR 좌표를 사용한 89개 조건에서 기존 판정 값과 터치 좌표가 모두 일치했습니다.
- 같은 비교에서 Bitmap 읽기 메서드 호출은 139,586회에서 1,304회로 99.07% 감소했습니다. Android 기기의 실제 FPS·배터리·처리 시간 개선율을 뜻하지 않습니다.

## 1.2.19 앱 연결 및 스크롤 개선

## 1.2.18 카브락 레이드 자동 반복

플레이에서 레이드를 선택하고 입문/어려움을 설정하세요. **중지 버튼을 누를 때까지 횟수 제한 없이 반복합니다.**

1. 캐릭터와 미니맵 정지를 순서대로 확인한 뒤 메뉴 → 레이드 → 카브락을 선택합니다.
2. 카브락 상세·혼자하기 초록·설정 난이도를 확인하고 이동합니다. 이동 중 연두색 날개 버튼을 인식해 누릅니다.
3. 상세를 다시 확인해 출항하기로 승선하고, 미니맵 배 위 위치를 연속 확인한 뒤 퀘스트 출항하기를 누릅니다.
4. 출항 영상과 보스방 진입 영상을 넘기고, 퀘스트 ‘카브락 클리어’를 정상 진입 표시로 인식합니다. 목표 문구 자체를 클리어 횟수로 세지 않습니다.
5. 음식 아이콘·두 줄 버프 조건을 어비스와 같은 방식으로 확인해 사이클당 한 번 사용합니다. 보스 이름·체력바·스킬창이 확인된 전투에서만 마지막 스킬을 약 20초 간격으로 누릅니다.
6. 처치 후 영상을 넘기고 카브락 처치 완료·전투 시간을 확인한 보상창에서 초록 확인 버튼을 누릅니다.
7. 토벌 완료·출항선 이동 안내를 확인하면 미니맵 옆 나가기 → 출항선으로 이동을 누릅니다. 포탈은 사용하지 않습니다.
8. 승선 미니맵과 출항 퀘스트를 연속 확인한 뒤 완료 횟수를 한 번 올리고 다음 출항을 준비합니다. 입력·음식·영상·스킬 타이머는 다음 사이클에 맞춰 초기화합니다.

레이드 관련 제어/이미지 검사 424개, 기존 검사 전체, APK 빌드·동일 인증서 서명·16KB 정렬·ZIP 검증을 통과했습니다. 사진 검사는 실제 이미지 픽셀과 제어한 OCR 좌표를 사용합니다. **실제 Android 기기의 OCR·터치·연속 플레이 성공은 아직 검증하지 않은 테스트 버전입니다.** 레이드 행동불능 화면에서는 추가 자료가 없어 대기하며 부활을 누르지 않습니다. 기존 어비스·뱅가드 판정 소스는 유지합니다.

## 1.2.16 성능 최적화와 공통 화면 모션

**설정 → 성능**에서 모드, 발열·기기 절전 연동, 분석 이미지 메모리 재사용과 성능 상태를 확인할 수 있습니다. 기본은 자동 최적화이며 두 연동/재사용 옵션을 켭니다.

- **자동 최적화:** 기존 인식 간격을 기준으로 입장·매칭 및 뱅가드 전투 대기에서 검사 간격을 늘립니다. 분석이 오래 걸리면 다음 검사 간격을 조정합니다. 부활·클리어·보상 버튼을 확인한 상태에서는 기본 반응 간격을 우선합니다.
- **빠른 반응:** 0.45초 기준. **절전:** 1초 기준, 대기에서는 1.6초 기준. **직접 설정:** 기존 0.45/0.65/1초 선택을 사용합니다.
- **발열·기기 절전 연동:** Android가 제공하는 발열 단계와 절전 상태를 읽어 캡처 간격을 늘립니다. 켜면 버튼 인식이 늦어질 수 있습니다.
- **메모리 재사용:** 709픽셀 폭의 분석 이미지를 재사용하고, 중지·메모리 압박 때 정리합니다. OCR이 사용 중인 이미지는 완료 뒤 해제합니다.
- **성능 상태:** 최근 실행의 분석 횟수, 평균/최근/최대 처리 시간, 적용 간격, 발열 단계와 보관 이미지·재사용 횟수를 표시합니다.

분석 완료 뒤 다음 검사를 예약해 대기 작업을 줄이고, 분석 작업 스레드 우선순위를 낮췄습니다. 빠르게 중지 후 다시 시작해도 캡처 시작 사이에 최소 간격을 둡니다. 어비스 부활·뱅가드 3회 종료 등 게임 판정과 동작 결정 코드는 유지합니다.

업데이트·설정 선택·입력·기록·도움말 창은 부드럽게 열리고 닫힙니다. 탭 전환과 버튼 누름에도 짧은 공통 효과를 적용했습니다. 새 버튼에도 같은 처리를 사용하며, 클릭 동작을 지연하지 않습니다. 기기 애니메이션 비활성화 설정을 존중합니다.

새 성능/메모리 검사 344개와 기존 전체 검사, APK 빌드·서명 검증을 통과했습니다. 실제 휴대폰의 FPS·발열·배터리 개선 폭과 새 화면 조작은 아직 측정/검증하지 않았습니다.

## 1.2.15 간편한 홈과 꾸미기

화면을 **플레이 · 꾸미기 · 설정** 세 메뉴로 나눴습니다. 플레이 화면에는 선택한 콘텐츠의 옵션과 게임 실행을 모으고, 긴 도움말·배포 주소·연결 설정은 따로 열 수 있게 정리했습니다.

**꾸미기 메뉴에서 바꿀 수 있는 항목**

- 밝게/어둡게 화면, 퍼플·민트·블루·코랄·모노 5가지 색상과 직접 색상 코드 입력
- 글자 크기 3단계, 카드/버튼 모서리 3단계, 화면 간격 3단계
- 홈 제목, 실행/플레이 설정 카드 순서
- 홈의 기록·업데이트·화면 확인 속도·사용 방법 표시 여부

변경 내용은 자동 저장하고 바로 적용합니다. 홈에서 숨긴 도구는 설정에서 다시 열 수 있습니다. 꾸미기 기본값 복원은 게임·난이도·목적지·종료 횟수 등 플레이 설정을 유지합니다. 사용자 지정 색상의 버튼 글씨와 강조 문구는 읽을 수 있는 대비를 계산합니다.

X로 닫는 별도 업데이트 정보창을 유지하고, 게임 화면 인식·부활·뱅가드 반복 로직은 1.2.14와 같습니다. 꾸미기 값·색상 대비·입력 경계 검사 284개, 기존 전체 검사 및 APK 빌드·서명 검증을 통과했습니다. 실제 Android 기기에서의 새 화면 조작과 설정 재실행은 아직 검증하지 않았습니다.

## 1.2.14 어비스 부활 수정

‘여기서 부활’ 버튼이 인식돼도 ‘행동불능’ 제목을 놓치면 누르지 않던 조건과, 하단 73~93%에만 제한했던 버튼 탐색 범위를 수정했습니다.

- ‘여기서 부활’ 버튼 자체로 부활 화면을 판단합니다. 제목만 보이고 버튼을 찾지 못하면 좌표를 추정해 누르지 않고 기다립니다.
- 화면 하단 절반에서 버튼을 탐색하고, ‘여기서’와 ‘부활’이 나뉘어 인식돼도 가까운 같은 줄의 글씨를 결합합니다.
- 여러 버튼이 하나의 OCR 줄로 묶였을 때 전체 줄 중앙 대신 부활 글씨 영역의 중심을 누릅니다.
- 부활 화면에서는 배경의 로딩·클리어 문구와 스킬·메뉴 조작을 우선하지 않습니다.
- 버튼이 계속 확인되면 2.5초 간격으로 재시도하고, 부활 후 전투 화면을 연속 두 번 확인한 뒤 일반 진행을 재개합니다.

부활 회귀 검사 45개와 기존 로직·사진·영상 재생 검사, Android 빌드·서명 검증을 통과했습니다. 부활 검사는 제어한 OCR 관측값을 사용하며, 실제 휴대폰에서의 인식과 터치 성공은 아직 검증하지 않았습니다. X로 닫는 별도 업데이트 정보창과 뱅가드 반복 동작은 유지합니다.

## 1.2.13 업데이트 안내 개선

업데이트 내용을 **별도 정보창**으로 옮겼습니다. 메인에는 작은 **업데이트 정보** 버튼을 표시해 플레이 설정을 바로 확인할 수 있습니다.

- 창 오른쪽 위 **X(×)** 를 눌러 닫습니다. 뒤로 가기나 창 바깥을 눌러도 닫을 수 있습니다.
- 변경 내용만 스크롤하며, 제목과 닫기 버튼은 위쪽에 고정됩니다.
- 새 버전 설치 후 처음 앱을 열면 한 번 안내합니다. 닫은 뒤에는 메인의 **업데이트 정보** 버튼으로 다시 엽니다.
- 주요 업데이트, 개선 사항, 버그 수정의 색상 구분은 유지합니다.
- 업데이트 확인 중·실패·최신 버전 상태와 새 버전 다운로드 버튼은 정보창 안에 표시합니다.

기존 게임 동작과 화면 분석 최적화는 유지합니다. Android 소스 컴파일, 기존 로직·사진·영상 재생 검사와 업데이트 분류 검사는 통과했습니다. 실제 Android 기기의 창 배치와 X 닫기 동작은 아직 검증하지 않았습니다.

## 업데이트 알림

기본 업데이트 주소와 새 버전 출시 알림, 버전별 중복 알림 방지, 백그라운드 확인이 포함됩니다. 설치 후 앱을 한 번 열고 알림을 허용하세요.

앱 실행 시 및 도우미 활성 중 약 1분마다 확인하며, 백그라운드에서는 약 15분 주기로 확인하도록 예약합니다. 절전 정책·네트워크·강제 종료 상태에 따라 확인이 지연되거나 중단될 수 있습니다. 다운로드와 설치는 사용자가 확인합니다.

향후 새 APK를 먼저 업로드하고, latest.json의 versionCode를 높여 버전명·APK 주소·변경 내용을 갱신하면 설치된 앱이 새 버전을 감지합니다.

어비스·레이드 관련 검사 및 APK 서명 검증을 통과했습니다. 실제 Android 기기의 OCR·터치·알림 UI는 아직 검증하지 않은 테스트 버전입니다.
